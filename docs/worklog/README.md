# 作業ログ

まとまった作業をしたら、ここに1ファイル残す。

## なぜ残すか

Claude Code の記憶（自動メモリ）は `~/.claude` 側にあり、**このリポジトリとは別管理**。
自宅PCと職場PCで開発を引き継ぐとき、リポジトリ内に残した記録だけが確実に一緒に付いてくる。
「何を、なぜ、どうやったか」が消えると、同じ罠を二度踏む。

## ファイル名

```
docs/worklog/YYYY-MM-DD-<topic>.md
```

例: `2026-08-20-invoice-payment-matching.md`

## 書く内容

```markdown
# <やったこと>

## 目的
なぜこれをやったか。どんな困りごとがあったか。

## 変更点
- 触ったファイルと、何をどう変えたか
- 関連コミット: <ハッシュ>

## ハマった点と原因
再発防止のため、原因まで書く。「動かなかった」だけでは意味がない。

## 残タスク
- [ ] 未着手のもの
```

## 残す基準

| 残す | 残さなくてよい |
|---|---|
| デプロイ・リリースを伴う変更 | typo修正、整形 |
| 設計判断（なぜその方式にしたか） | 手が滑った修正 |
| 事故と復旧 | 依存の定期更新 |
| ハマった罠と回避方法 | |
| 環境構築・鍵まわりの手順 | |

## 書いてはいけないこと

- パスワード、APIキー、キーストアのパスフレーズなどの秘密情報
  （置き場所の説明までに留める）
- 個人情報
